Сайт в Docker: от файла до контейнера

Цель: понять принципы контейнеризации, освоить синтаксис Dockerfile, собрать собственный образ и управлять его запуском.

Подготовка рабочей среды

15–20 мин

Нужны Docker Desktop (на Windows — с включённым компонентом WSL 2; на macOS — версия под Apple Silicon или Intel) и VS Code либо любой текстовый редактор.

Откройте PowerShell (Windows) или Терминал (macOS) и проверьте установку:

docker --version
Если отображается версия Docker, среда готова к работе.

Шаг 1. Структура проекта и файлы сайта

25 мин
  1. Создайте на рабочем столе папку my-docker-site.
  2. Перейдите в неё через терминал:
cd $HOME\Desktop\my-docker-site
cd ~/Desktop/my-docker-site
  1. Создайте в папке файл index.html и вставьте код:
<!DOCTYPE html>
<html lang="ru">
<head>
    <meta charset="UTF-8">
    <title>Мой первый сайт в Docker</title>
    <style>
        body {
            font-family: Arial, sans-serif;
            background-color: #f0f4f8;
            display: flex;
            justify-content: center;
            align-items: center;
            height: 100vh;
            margin: 0;
        }
        .card {
            background: white;
            padding: 30px;
            border-radius: 10px;
            box-shadow: 0 4px 6px rgba(0,0,0,0.1);
            text-align: center;
        }
        h1 { color: #2c3e50; }
        p { color: #7f8c8d; }
    </style>
</head>
<body>
    <div class="card">
        <h1>🚀 Сайт успешно запущен внутри Docker!</h1>
        <p>Практическое занятие по облачным технологиям.</p>
    </div>
</body>
</html>

Так страница будет выглядеть в браузере:

http://localhost:8080

Шаг 2. Создание и разбор Dockerfile

30 мин

В той же папке создайте файл с точным названием Dockerfile — без расширений вроде .txt или .html. Добавьте в него код. Нажимайте на строки, чтобы увидеть разбор директив.

# 1. Используем официальный легковесный образ веб-сервера Nginx на базе Alpine Linux
FROM nginx:alpine

# 2. Копируем файлы нашего сайта в директорию, откуда Nginx раздаёт статику
COPY index.html /usr/share/nginx/html/index.html

# 3. Указываем, что контейнер слушает порт 80
EXPOSE 80

# 4. Запускаем Nginx в режиме foreground (чтобы контейнер не завершал работу)
CMD ["nginx", "-g", "daemon off;"]

Шаг 3. Сборка Docker-образа

20 мин

Убедитесь, что терминал открыт в папке my-docker-site, и выполните сборку. Точка в конце обязательна.

docker build -t my-first-site:v1 .
  • -t my-first-site:v1имя образа (my-first-site) и его тег-версия (v1)
  • .Docker ищет Dockerfile в текущей рабочей директории

Проверьте, что образ появился в локальном реестре:

docker images

Шаг 4. Запуск и проверка контейнера

20 мин
docker run -d -p 8080:80 --name student-web-container my-first-site:v1
  • -ddetached — запуск в фоновом режиме
  • -p 8080:80порт 8080 вашего ПК связан с портом 80 внутри контейнера
  • --nameпонятное имя запущенного контейнера

Откройте в браузере http://localhost:8080 — должна появиться карточка «Сайт успешно запущен внутри Docker!».

Шаг 5. Управление контейнерами и отладка

20 мин

Отработайте основные команды управления по порядку.

Запущенные контейнеры

docker ps

Логи веб-сервера

docker logs student-web-container

Остановка

docker stop student-web-container

Удаление

docker rm student-web-container

Контрольные вопросы для защиты

В чём главное отличие Docker Image (образа) от Docker Container (контейнера)?

Подумайте: что из них — неизменяемый шаблон, а что — работающий экземпляр? Сколько контейнеров можно запустить из одного образа?

За что отвечают параметры -p 8080:80 при запуске docker run?

Какой порт слева, а какой справа? Где находится каждый из них — на вашем ПК или внутри контейнера?

Зачем нужна директива COPY в Dockerfile?

Где в момент сборки находятся файлы сайта и куда они должны попасть, чтобы Nginx мог их раздавать?

Почему для контейнеризации статических сайтов часто выбирают дистрибутив alpine?

Сравните размер образа с обычными дистрибутивами и подумайте, что это даёт при сборке и загрузке.
